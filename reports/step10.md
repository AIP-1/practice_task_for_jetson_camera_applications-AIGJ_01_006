# 10단계 두 카메라 접근 감지 — 결과


**요약**: 두 카메라로 사람과 타겟(바닥의 한 점) 사이 거리를 재는 단계입니다. 2호기 USB C920(cam0)과 1호기 USB C920(cam1, Tailscale 로 MJPEG 수신)을 쓰고, 2호기에서 계산합니다.
- **결과**: 최종 배치 5 에서 ankle1 은 0.5m·1.0m 목표 자리를 각각 **0.76m·1.28m** 로 쟀습니다(자리별 줄자 값은 따로 기록하지 않음). 오차는 거리와 상관없이 **약 +27cm 로 일정**했고, 흔들림은 1cm 이하, 25.5 fps 였습니다. 1일차 좁은 공간(배치 4)에서는 자로 잰 0.52m 를 **0.52m(오차 0)** 로 쟀습니다.
- **한계**: 카메라가 바닥 쪽으로 숙여져 있어, 2m 이상에서는 발이 화면 위로 벗어났습니다(보인 비율 0~4%). stereo·fused 는 어깨·코가 화면 밖이라 한 번도 측정되지 않았습니다(아래 10-7 표와 문제 해결 31).
- **결정**: 카메라를 들고 다시 보정하는 대신, 10-28 에 이대로 마무리했습니다(민서 결정).
- **하지 않은 것**: 10-6 타겟 자동 찾기·접근 알람 시나리오, 10-8 이동 타겟, 확장 과제(MQTT)는 진행하지 않았습니다. stereo 가 0% 로 나오자 fused 를 전제로 하는 단계로 보고 함께 미뤘는데, 돌아보면 타겟 자동 찾기(물체를 두 카메라로 잡음)와 1m 안쪽 알람(ankle1 모드에서도 동작)은 같은 구도에서도 해 볼 수 있었습니다. 마무리를 정할 때 이 점을 짚지 못했고, 카메라를 철거해 다시 재지 않았습니다. 강의자료 대비 점검은 [01-self-grade.md 6절](01-self-grade.md#6-10단계-점검-2026-10-28-추가)에 있습니다.

근거는 [`results/10_calib.jsonl`](../results/10_calib.jsonl), [`results/10_extrinsics.jsonl`](../results/10_extrinsics.jsonl), [`results/10_proximity.jsonl`](../results/10_proximity.jsonl) 입니다. 버린 기록도 지우지 않고 `note` 에 이유를 적었습니다.

측정 조건: 2호기 MAXN_SUPER, 640x480, YOLO11n-pose, 타겟은 바닥 보드 가운데 (0.08, -0.05) m(마우스로 표시), 위치마다 10초(0.2초 간격 50회).

읽는 법:
- **오차의 기준**: 10-28 의 0.5·1.0m 는 목표 거리 자리에 선 값이고, 자리마다 줄자로 다시 잰 값은 jsonl 에 없습니다(`note`: 실측값 따로 안 받음). 그래서 아래 +27cm 에는 서는 자리의 오차도 섞여 있을 수 있습니다. 줄자로 확인한 거리는 10-27 의 0.52m(오차 0.00) 하나입니다.
- **ankle1 오차가 일정한 이유 (추정)**: 0.5m 와 1.0m 의 오차가 +0.26 / +0.28 m 로 거의 같습니다. 보정 비율이 틀렸다면 거리에 비례해 커졌을 것이므로(1.0m 에서 +0.52), 위치가 한쪽으로 밀린 것으로 봅니다. 두 원인을 나눠 계산했습니다.
  - 발목 키포인트는 바닥보다 약 8cm 위에 있는데, ankle1 은 이를 바닥(z=0)으로 봅니다. 높이 1.22m 카메라가 비스듬히 보면 수평거리 × 0.08 / 1.14 만큼 멀게 나옵니다. 0.5m 자리에서 약 +13cm, 1.0m 자리에서 약 +17cm 입니다.
  - 남는 +12cm 정도는 마우스(타겟)를 보드 가운데보다 조금 옮겨 놓은 탓으로 봅니다.
  - 두 점만으로 낸 추정입니다. 앉은 자세가 +0.10m 로 작은 것은, 앉으면 발이 카메라 쪽으로 들어오기 때문으로 봅니다(실측 없음).
- **stereo 가 0% 인 이유**: 두 카메라 모두 사람은 잡았지만(프레임 4쌍 확인), stereo 는 어깨 중심(없으면 코)을 두 카메라에서 맞춰 삼각측량합니다. 카메라를 바닥 보드에 맞춰 숙이다 보니 다리만 화면에 들어왔습니다. 위치 보정에는 좋은 구도였지만 접근 감지에는 나쁜 구도였고, 측정 전에 상체가 보이는지 확인하지 않은 것이 원인입니다(문제 해결 31).
- **자원**: stereo 는 두 영상을 모두 포즈 추론해서 ankle1 보다 fps 가 15% 낮았습니다(25.5 → 21.7). GPU 평균은 20 → 30%, 전력 평균은 9.5 → 10.9 W 로 올랐습니다. 두 카메라 시간 차 15.5 ms 는 허용치 80 ms 안입니다. 1호기 영상이 Tailscale 을 거쳐 오는데도 동기화는 문제가 되지 않았습니다.

### 10단계 오프라인 분석 (2026-10-28, 카메라 철거 뒤, 새 측정 없음)

카메라를 철거해 다시 잴 수 없어서, 저장소에 남은 보정 결과와 앱 코드만으로 **계산과 시뮬레이션**을 했습니다. 아래 숫자는 실측이 아니며, 실측(위 10-7 표)과 맞는지 대조하는 데만 씁니다. 근거는 [`prox/offline_10.py`](../prox/offline_10.py) → [`results/10_offline_sim.json`](../results/10_offline_sim.json), [`prox/test_alarm_offline.py`](../prox/test_alarm_offline.py) → [`results/10_alarm_offline.jsonl`](../results/10_alarm_offline.jsonl) 입니다.

- **입력**: 배치 5 카메라 위치(`10_extrinsics.jsonl`), 최종 렌즈 행렬 K(`10_calib.jsonl`), 앱의 실제 함수(`stereo.py` 의 `project`·`ray_plane`·`triangulate`, `proximity_app.py` 의 `ProximityAlarm`).
- **가정 (실측 아님)**: 카메라 방향(R)은 2호기 `calib/*.npz` 에만 있어서 "광축이 보드 가운데를 향함" 으로 두었습니다(계산하면 cam0 41.6°·cam1 39.0° 아래). 렌즈 왜곡은 무시했고, 발목 0.08m·어깨 1.40m·코 1.60m, 사람은 타겟에서 카메라 반대쪽에 선다고 봤습니다.

- 이 구도에서 바닥 보드는 화면 밖입니다. 9x6 2cm 보드는 0.40m 높이(의자)에 올려야 두 화면에 들어오지만 폭이 33~37px 로 기준(60px)보다 작습니다. 이미 만들어 둔 **큰 보드(7x4, 칸 9cm)를 0.50m 높이**에 두면 106~124px 로 기준을 넘습니다 → `--board-height 0.5`.

**4) 10-6 접근 알람 로직 (합성 거리 신호, 실제 카메라 아님)**

`ProximityAlarm` 소스를 앱에서 그대로 꺼내, 강의자료 10-6 시나리오를 거리 시계열(10 Hz, 1 m/s, 잡음 σ 0.02m)로 만들어 각 3회 돌렸습니다(`--near 1.0 --far 3.0`).

| 시나리오 (3회씩) | 기대 결과 | 맞은 횟수 (수정 전 → 후) | 비고 |
| --- | --- | --- | --- |
| 4m에서 타겟으로 걸어옴 | 접근 시작 → 알람: 근접 | **0/3 → 3/3** | 수정 전에는 "접근 시작" 이 한 번도 안 나옴 (문제 해결 32) |
| 타겟 앞 0.5m에서 4m 밖으로 나감 | 알람: 이탈 | 3/3 → 3/3 | 이탈 3.06m 에서 1회 |
| 1.0m 경계에서 10초 서 있음 | 알람 1회만 | 3/3 → 3/3 | 히스테리시스 0.2m 로 깜빡임 없음 |
| 타겟 2m 옆을 지나감 | 근접 알람 없음 | 3/3 → 3/3 | 근접은 없지만 3m 밖으로 나갈 때 "이탈" 알람이 1회 울림(개선 거리) |
| 타겟 옆 책상에 앉음 (0.6m) | 근접 알람, 자세 = 앉음 | 3/3 → 3/3 | 자세는 stereo 높이가 있어야 해서 확인 못 함 |

- **잡음에 대한 여유**: 1.0m 경계에 10초 서 있을 때 근접 알람 수는 σ 0.02·0.05m 에서 1회, σ 0.10m 에서 2~3회, 0.20m 에서 6~16회였습니다. 위 3) 의 3m stereo 오차(95% 23cm)라면 경계 부근에서 깜빡일 수 있어, 먼 경계는 `margin` 을 키우거나 위치 중앙값 창을 늘려야 합니다.
- **ankle1 편향이 알람에 주는 영향**: 측정 거리에 +0.27m 를 더하면 근접 알람(1.0m)이 실제 0.73m 이하에서야 울립니다(10 Hz 표본으로는 0.61m 에서 처음 울림). 편향을 보정하지 않으면 근접 알람이 약 27cm 늦습니다.

**다음에 10단계를 다시 잴 때의 절차 (위 계산으로 정한 값)**

1. 카메라 두 대를 지금처럼 나란히(약 0.7m) 두되, 12° 정도만 숙여 0.5~3m 자리에서 어깨~발목이 두 화면에 다 보이게 합니다(측정 자리에 사람이 먼저 서서 확인).
2. 큰 보드(7x4, 칸 9cm, `checkerboard_7x4_9cm_A4x8.pdf`)를 의자 위 약 0.5m 높이에 올리고 `calib_extrinsics_board.py --cols 7 --rows 4 --square 0.09 --board-height <잰 높이>` 로 보정합니다. 화면 속 보드 폭 100px 이상, 두 번 잰 위치 차이 10cm 이하를 확인합니다.
3. 바닥에 0.5·1·2·3m 테이프를 붙이고 줄자 값을 `measure_10_7.py --true-d` 에 넣은 뒤에만 시작합니다(문제 해결 29 의 재발 방지).
4. ankle1 → stereo → fused 순서로 같은 자리를 재고, 이어서 10-6 시나리오 5개를 3회씩 합니다. 알람 로직은 `python test_alarm_offline.py` 로 미리 확인해 둡니다.
